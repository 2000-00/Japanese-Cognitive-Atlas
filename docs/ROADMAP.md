# Minna Japanese Trainer — 模块化开发路线图

> 本文件由用户与 Claude 共同确定（2026-07）。以后每次开发会话围绕
> **一个模块**推进，不零散加功能。动工前先读本文件与
> `TRAINER_GUIDE.md`，完工后更新对应模块的状态栏。

## 总原则（最高优先级，凌驾于所有模块之上）

> 任何新增内容，不应首先考虑增加题目数量，而应首先考虑增加高质量、
> 可复用、真实生活化的**语料**。
> 所有训练形式（听力、阅读、语法、数字、词汇、影子跟读、综合训练）
> 都应尽可能由**同一份语料**自动派生。
> 系统的核心资产是**语料库**，其次是**知识图谱**，最后才是题库。

真实性原则继续有效：不虚构教材原文、不猜测课程归属、AI 生成内容
必须携带 `contentType: ai_generated_practice` 标记、待核实内容不进
正式训练（详见 TRAINER_GUIDE.md）。

### 教材词表录入（下一步的关键人工前置）

（sourceStatus 由 pending→verified）。录入后覆盖率、缺口扫描、按词生成
才真正生效。**AI 不得凭记忆填写教材词表。**

## 模块 1：音频系统升级

**目标**：正式训练不依赖浏览器实时 TTS；建立可验证的音频流水线。

```
文本 → AI TTS → MP3 → 缓存 → 自动校验（ASR/Whisper 逐字比对） → 正式题库
```

- 浏览器 SpeechSynthesis 降级为：开发调试／临时试听／无正式音频时的备用。
- 校验不一致 → 重试；连续三次失败 → 标记 `pending_audio`，禁止进入正式训练。
- **技术要点（沙盒/静态站约束）**：TTS 与 Whisper 无法在纯前端运行，
  需要离线生成流水线——建议 `scripts/audio-pipeline/`（Node/Python）+
  GitHub Actions 定期跑；产物 MP3 放 `assets/audio/<hash>.mp3`，
  数据条目回填 `audioUrl` 与 `audioStatus: verified|pending_audio`。
  播放侧无需改动：speech.js 已优先播放 audioUrl、失败退 TTS。
- 验证器新增：正式训练条目若 `audioMode: 'file'` 必须有已验证 audioUrl。

## 模块 2：语料库系统

**目标**：系统围绕**场景**组织，不围绕题目。

- 建立 `data/corpus/<场景>/`：便利店、医院、学校、银行、牙科、电车、
  邮局、超市……每个场景至少：对话、阅读、听力、Shadowing、综合、数字。
- 定义统一语料 schema（一段对话/短文 + 逐句标注：假名/翻译/语法点/
  数字信息/听错陷阱/词汇及出处标记），所有训练从语料**自动派生**，
  不再人工写题。现有 scenario 步骤结构是 schema 的起点。
- 迁移策略：现有 14 个场景转为语料条目；阅读/听力题库逐步改为
  "语料+派生规则"。

## 模块 3：教材词汇覆盖统计

- 数据前提：**用户提供**《大家的日本语》1～21课词汇清单（AI 不得
  自行编造教材词表——真实性原则）。录入 `data/lessons/vocabulary-*.js`，
  逐课登记，来源标 user_material。
- 系统对语料做分词比对，输出每课 `总词汇/已覆盖/未覆盖` 及清单；
  之后每个开发会话自动补未覆盖词的语料，直到 100%。

## 模块 4：扩展词汇（已完成，维持规则）

- 教材词汇为主体（80%～90%）；扩展词只允许基础生活词，必须
  `scope: extended_basic` + 假名/中文/词性/出现原因/是否建议学习。
- 每场景≤5个；不能成为主要考点；设置页三档开关（默认少量扩展）。

## 模块 5：情景训练入口

- 训练入口从"题型优先"翻转为"场景优先"：
  `便利店 → 听力 → 阅读 → 语法 → 数字 → Shadowing → 综合 → 结束`。
- 实现：场景详情页聚合该场景派生的全部训练形式，一键连续完成；
  首页入口以场景卡为主，题型页保留为"横切入口"。

## 模块 6：词类变形系统

- 情景变形训练：动词／い形容词／な形容词／名词 × 八种基本形式
  （现在肯定/否定、过去肯定/否定 × 敬体/普通体）。
- **禁止孤立背表**：变形必须出现在完整文章/对话/故事里，作答后
  解析"为什么这里是 静かでした 而不是 静かです"（时间线索、语体）。
- 从语料派生：给语料句子标注变形槽位即可自动生成。

## 模块 7：能力驱动

- 统计与推荐从"第8课完成80%"改为能力维度：时间/金额/数量词/助词/
  て形/ない形/普通体/敬体/听力/阅读……每项独立正确率+反应时间。
- 今日训练由能力短板自动决定。现有 adaptive.js + mastery.js 扩展即可。

## 模块 8：词汇浸泡

- 选定重点词（如 予約）后，未来 N 天的各场景训练中反复自然出现，
  直到该词在 ≥4 个场景表现稳定（复用 mastery 机制，粒度=词汇）。

## 模块 9：知识图谱联动

- 已有：题目/场景 → Atlas 节点（knowledgeMap，只用真实节点）。
- 待做：反向联动——在图谱页点某节点（如 〜てもいいです）自动列出
  该节点关联的全部听力/阅读/Shadowing/综合训练与例句，可直接开练。

## 模块 10：大型语料工厂

- Claude 的产出单位从"题"改为"语料"：
  `场景 → 语料 → 审核 → 正式语料 → 自动派生（听力/阅读/语法/
  Shadowing/综合/数字/作文/口语）`。
- 依赖模块 2 的 schema 与派生器；派生器写成纯函数便于测试。

## 模块 11：审核系统调整

- 审核对象从"一道题"改为"一份语料"：主要核实教材课程归属、语法
  标签、场景标签、来源。审核通过 → 自动进入 `data/verified/` 并
  立即进入正式训练（现有 reviewDecisions 机制升级为语料级）。

## 模块 12：统计系统（覆盖率仪表盘）

- 首页增加：教材/词汇/场景/语法/数字/听力/Shadowing/阅读/综合
  各项覆盖率；按课（第1课 100% … 第21课 82%）与按场景
  （医院 87%／便利店 95%／学校 42%）两个维度展示。
- 依赖模块 2 的语料标签与模块 3 的词汇清单。

## 建议推进顺序

1. **模块 2（语料 schema + 现有场景迁移）** —— 一切派生的地基
2. 模块 10 的派生器（听力/阅读/数字先行）

5. 模块 5 情景入口翻转 → 模块 6 变形 → 模块 8 浸泡 → 模块 9 反向联动
